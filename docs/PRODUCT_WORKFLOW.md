# Product Workflow

## 1. 产品目标

Tomoni 根据用户长期进行的固定计划，推荐时间、活动和大概区域相近的人，让用户先了解对方，再通过聊天发出一次具体同行邀请。

## 2. 核心流程

```text
注册或登录
→ 创建固定计划
→ 设置个人资料
→ 系统生成推荐
→ 查看对方资料
→ 打招呼
→ 进入聊天
→ 发送具体同行邀请
→ 对方接受
→ 创建正式 Meetup
→ 按时间地点见面
→ 活动后反馈
→ 决定是否继续联系
```

## 3. Onboarding

### 登录判断

```text
首次登录 → 进入 Onboarding
已完成设置 → 进入首页
未完成设置 → 回到上次步骤
```

必须处理：

- 登录中
- 登录失败
- 用户取消
- 网络断开
- 未完成设置后离开

### 固定计划

每个 FixedSchedule 包含：

- 活动类型
- 星期
- 时间段
- 大概区域或公共地点

MVP 规则：

- 一个计划只选择一个活动类型
- 星期可以多选
- 时间段先使用固定选项
- 至少保留一个有效计划
- 首次设置最多建议三个计划

### Profile

建议字段：

- 昵称
- 头像
- 年龄段
- 性别，可选
- 使用语言
- 简短介绍

不得要求用户公开真实姓名、电话或邮箱。

## 4. 推荐

硬性过滤：

- 活动类型相同
- 星期有重合
- 时间段有重合
- 地点距离符合范围
- 双方没有 Block
- 双方账号状态正常

排序：

- 时间重合程度
- 距离
- 计划重复频率
- 语言和年龄偏好
- 最近活跃程度

## 5. 连接流程

顺序固定为：

```text
查看资料
→ 打招呼
→ 聊天
→ 发送同行邀请
```

Invitation 被接受前，不显示：

- 精确地址
- 电话
- 邮箱
- 实时位置
- 完整生活路线

## 6. 聊天

MVP 支持：

- 一对一文字消息
- 发送状态
- 发送失败重试
- Invitation 卡片
- 系统状态消息

第一版暂缓：

- 图片
- 文件
- 语音
- 视频
- 已读状态
- 消息撤回

## 7. Invitation

Invitation 是一次具体提议，不是 FixedSchedule 的复制。

必须填写：

- 活动
- 日期
- 开始时间
- 结束时间
- 集合地点
- 补充说明

接收方可以：

- 接受
- 拒绝
- 协商修改

## 8. Meetup

对方接受后：

1. Invitation 变为 `accepted`
2. 创建唯一 Meetup
3. Meetup 变为 `confirmed`
4. 双方收到通知
5. 双方首页显示同行计划
6. 解锁精确集合地点

## 9. 取消

Invitation 未接受：

```text
pending → withdrawn
```

Meetup 已成立：

```text
confirmed → cancelled
```

取消后保留记录并通知双方。

## 10. 活动后反馈

```text
in_progress
→ awaiting_feedback
→ completed / no_show
```

用户可以选择：

- 已见面
- 没有见到
- 对方没有出现
- 是否希望再次同行

## 11. 通用页面状态

所有异步页面必须处理：

- Loading
- Empty
- Error
- Offline
- Disabled
- Duplicate submission
